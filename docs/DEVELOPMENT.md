# Developer notes

Notes kept while building Sterling Quest Sync (formerly Sterling Quest Tracker) for WoW Forever: what the client allows, the Lua and UI traps that bit, how the tests work, and a version-by-version record of how each part of the add-on works. Names of players in examples are made up.

- Code: `Sterling/` (load order is in `Sterling.toc`).
- Tests: `qa/`. Run `bash qa/all.sh` (Python 3 with `lupa` and `Pillow`). `qa/fixtures/sterling-6.29/` is an old build used to test that old and new copies still sync.
- Releases: zipped `Sterling/` folder plus `release.json` (for WowUp) on the GitHub releases page. `python3 qa/zipcheck.py <zip>` checks a zip holds no runnable files.

## WoW Forever addon restrictions (confirmed Nov 11)

- Forever runs on the retail **Midnight** client with Midnight's addon rules.
- **The combat log is closed to addons.** `CombatLogGetCurrentEventInfo` does not exist; a probe got zero combat log events. Chat combat text is a protected string addons can show but not parse.
- Some values are "secret" in combat (health, threat, auras, enemy spells). Wrap aura reads in pcall and check `issecretvalue` when it exists.
- So anything built on "who hit what" (trap break attribution, resist detection from the log) is off the table. Decided: drop combat log features for now.
- Old global APIs missing here: `GetMerchantItemInfo` (use `C_MerchantFrame.GetItemInfo`), `GetSpellBookItemName/Info` (use `C_SpellBook`), `GetItemInfoInstant` (use `C_Item.GetItemInfoInstant`), `GetFactionInfo` (use `C_Reputation`), `GetPetHappiness`, `GetPetFoodTypes`, `GetPetLoyalty`, `EquipItemByName`, `ContainerIDToInventoryID` (use `C_Container`).
- **`EasyMenu` and `UIDropDownMenuTemplate` don't exist.** Right-click menus built on them silently do nothing. Sterling has its own menu (`S.ShowMenu(items, anchor)`, submenus via `menuList`, closes on outside click with `GLOBAL_MOUSE_DOWN`). Reuse it.
- `UNIT_HAPPINESS` fires constantly for every unit (player, pet, targettarget), so it's useless as a pet happiness signal.
- `UnitName("player")` returns only the first word for names with spaces ("Kaelith" for "Kaelith Emberfall"). Other players' addon messages carry the full name, and the group echoes your own addon messages back to you.

## Lua and client gotchas (all hit for real)

- **WoW runs Lua 5.1.** Test syntax with lupa's `lua51` runtime, not the default (5.4+ treats `goto` as reserved, 5.1 doesn't, and the reverse problems exist too).
- **A `local function` must be defined above every line that calls it.** Calling one defined further down is `nil` at runtime ("attempt to call a nil value"). Scan for this before every ship.
- **Never put code after a `--` comment on the same line.** In 5.82 a comment swallowed `ClearAllPoints` / `SetPoint` / `Show`, so the gold side line never drew.
- **`SetScript` replaces hooks.** If a shared builder has done `HookScript("OnShow", ...)`, a later `SetScript("OnShow", ...)` wipes it. Use `HookScript` on anything built by `Window()`.
- **Frames that overlap need their own layer:** `SetToplevel(true)` plus `Raise()` on show and mouse down, or two windows at the same strata draw through each other.
- **`PanelTabButtonTemplate` re-sizes tabs to their text** when shown or selected, a frame later. Re-apply your own widths after selecting and again on the next frame.
- **`UIPanelCloseButton`'s default OnClick hides its parent.** A close button that isn't a direct child of the window needs its own OnClick that hides the window.
- **A child frame always draws over its parent's own regions** (textures, font strings), whatever the draw layer.
- **`gsub` returns two values (string, count).** Passing `x:gsub(...)` straight into a function with a second parameter leaks the count in as that argument. Wrap it in parentheses: `f((x:gsub(...)))`. This blanked every Sterling objective's text until 5.29 (`safe()` took the count 0 as the max length).
- **`OnDoubleClick` only exists on Buttons.** Setting it on a plain Frame errors and aborts the rest of the build function.
- **Many old texture paths don't exist on this client** (old minimap pins, ping rings). Use `SetColorTexture`, `CreateLine`, or atlases via `SetAtlas` with a pcall and a fallback.
- **Custom textures:** 64x64, 32-bit uncompressed TGA with top-left origin (descriptor 0x28), written with our own Python (PIL). ImageMagick's TGA writer came out upside down. New texture files need a full game restart.
- **Lines:** use `CreateLine()` (native). The old rotated "TaxiFrame line" trick draws nothing here.
- **Map art:** `C_Map.GetMapArtLayers` / `GetMapArtLayerTextures` for base tiles; explored patches from `C_MapExplorationInfo.GetExploredMapTextures`. Unexplored patches have to come from a reveal table (Leatrix Maps data), keyed by **uiMapID**. This client renumbered art IDs, so art-ID keys don't match.
- **Race faces:** atlas `raceicon-<race>-male`. Skyborne (Forever-only race, looks like high/blood elves) is tried as `raceicon-skyborne-male` first, Blood Elf as the stand-in.
- **An empty multi-line EditBox has zero height**, so clicks miss it. Give it a minimum height, a visible field behind it, and focus it from the scroll frame's OnMouseDown.
- **Backdrop frames default to white** unless you set `SetBackdropColor`.
- **Colour picker:** retail uses `ColorPickerFrame:SetupColorPickerAndShow(info)` (`swatchFunc`, `opacityFunc`, `cancelFunc`, `GetColorAlpha`). Older clients use `.func` / `.opacityFunc` / `.cancelFunc` plus `ShowUIPanel`, with opacity inverted.
- **Addon messages:** `C_ChatInfo.SendAddonMessage`, about 255 bytes each, roughly 3 a second. Chunk long strings and queue them. Whisper only people known to be online, or you get "No player named X is currently playing" spam.
- **Edit boxes double `|`.** Use `^` and `:` as separators in export strings.
- **SavedVariables are written on logout and `/reload`.** A brand-new .lua file needs a full game restart, not a reload.
- **Renaming a SavedVariables table:** list both names in the toc (`SterlingQuestDB, SterlingDB`), copy the old table over once in ADDON_LOADED, then set the old one to nil. The file name follows the folder, so keep the folder name.
- **Transport detection:** `UnitOnTaxi` for flights. For boats/zeppelins, watch for a continent change (`C_Map.GetWorldPosFromMapPos` returns the continent). Ignore all position jumps while `UnitIsDeadOrGhost`.

## Testing without the game

- A stub WoW API (frames, textures, timers, events) loaded into lupa, then the addon files run against it. It catches load errors, nil calls, wrong argument shapes and logic bugs.
- Two lupa runtimes wired together simulate two players syncing, including reloads and dropped messages.
- **The suite lives in `qa/`** (geometry stub, multi-player simulator, layout audit; `all.sh` runs it all). Run the layout audit after any UI change: it catches overlaps, text under buttons and things off the edge without a screenshot.
- Older scenario files in `qa/old-scenarios/`: smoke.lua and smoke_navy.lua (every button, hover, wheel, log style, preset and slash command in both skins), look.lua (live skin switch), appear.lua (colour picker and Custom look), place.lua (side window placement), cu.lua / cupath.lua (catch-up), npc.lua (tooltips), sect.lua, sess.lua, me.lua / me2.lua (self detection), stranger.lua.
- It does not catch: missing textures, layering, exact font widths. Those need a look in game. (Layout overlap is now measured, with estimated text widths.)

## Data that can be mined

- **Questie** saves a per-character `journey` in `SavedVariables\Questie.lua` (QuestieConfig.char["Kaelith Emberfall"].journey): every quest Accept / Complete / Abandon and level-up, with timestamps. Quest names are not in it; Sterling's own name cache (`SterlingQuestDB.names`) has them.
- Questie's quest/NPC database is a compiled binary blob in the same file (questBin/npcBin), not easy to read. Read it at runtime through `QuestieLoader:ImportModule("QuestieDB")` instead.

## Sterling Quest Sync: how it works, version by version

Records a play session (positions, quests, flights, boats, hearths, dungeons, levels, deaths, notes), exports it as a string, and lets a friend follow it with a TomTom arrow, a Path checklist, its own map window with playback and a timeline, plus quest-log sync and compare between any number of partners, a Catch-up planner, and partner quest status on tooltips and in the quest log.

- Folder `Sterling`. Load order: Libs (LibStub, ChatThrottleLib, LibDeflate), Core.lua (data, sync, offline sync, path engine, slash), Theme.lua (skin, fonts, tabs), Record.lua (recorder, sessions, encode/decode), Map.lua (world map overlay, minimap trail), Reveal.lua (unexplored map data), Viewer.lua (map window + timeline + session compare), UI.lua (windows, tabs, Options, menus), Status.lua (partner quest status on tooltips and quest log), Catchup.lua (Catch-up planner), Guide.lua (welcome, tour, tips, Help), Bindings.xml, Media.
- **Names (0.3.13):** everything visible says "Sterling Quest Sync" (window, AddOns list, minimap tooltip, keybind header, help, chat prefix). The desktop app is "Sterling Quest Sync Companion" and its small add-on "the Companion add-on". Code names below are unchanged.
- **Names (5.30):** everything visible says "Sterling Quest Tracker". Code names are `SterlingQuest`: saved data `SterlingQuestDB` (migrated from `SterlingDB`), frames `SterlingQuest*`, keybinds `STERLINGQUEST_*`, slash list `STERLINGQUEST`, addon message prefix `SterlingQuest`. Slash commands stay `/stq`, `/sterling`, `/st`.
- Sync protocol number lives in `S.VERSION` (now 6). Bump it on any change to the sync message format so mismatched copies refuse each other. The addon version (`S.ADDON_VER`, from the toc) travels in `AVER`.
- Sessions: right-click for Follow, Map, Export, Send, Rename, Merge, Compare, Delete. Delete asks first and goes to a trash of the last 5; a Restore button on the Sessions page brings the latest back.
- **Partner quest status (5.32, Status.lua):** under each quest title Questie adds to a mob/object/item tooltip, a line per state (nothing if no partner started it). In the quest log, a block under the quest title. Data comes from synced snaps (`S.snaps[name].log` / `.completed`). Tooltips: titles matched by name (Questie's "[37]" prefix stripped), tagged so they're never added twice; hooks `GameTooltip:Show` and TooltipDataProcessor post-calls.
- **Map pin tooltips (5.33):** Questie's world map and minimap pins render into GameTooltip (`MapIconTooltip.lua`, rows via `TooltipLayout`), with each quest title led by a texture: its blank spacer `|TInterface\Minimap\UI-bonusobjectiveblob-inside.blp:1:<w>|t` or the reputation icon. The title matcher strips `|T..|t` and `|A..|a`; the status line reuses the spacers.
- Questie's source is on the PC (`AddOns\Questie`); stage files from it to check formats instead of guessing.
- **Nicknames and partner info (5.35):** right-click a partner in the Sync list for Set nickname / Clear nickname / Compare / Remove. `SterlingQuestDB.nicknames[charName]`; `S.PartnerLabel(name)` = your nickname, else their chosen profile name, else character first name.
- **Partner status only covers the Sync list (5.34):** never yourself; saved snapshots of anyone not in the Sync list are dropped at login.
- **Bug fixed in 5.35:** 5.32's `S.PartnerStatus(qid)` in Status.lua overwrote Core's `S.PartnerStatus(name)` (online check). Quest status is now `S.QuestPartnerStatus`. Lesson: grep for an `S.` name before defining it in a new file.
- Character names on Forever can have spaces ("Kaelith Emberfall", "Brannoc Ashvale").
- **Sync fix (5.36):** a direct request (REQ or SINCE) always gets an answer straight back to the asker: the full log, a replay plus any changes since, `CUR` (nothing new) or `OFF` (they have you unchecked).
- **Sync status in chat (5.36):** `S.SyncWith(name or nil, "quick"|"send"|"receive"|"full")`. Chat shows "Sync started" and "Sync complete", "switched off on their side", or after the timeout "didn't finish" with what's missing.

- **Quest log panel moves (5.38):** the quest details panel (`QuestInfoTitleHeader`) gets re-parented between the quest log and the world map's quest panel. Keep one status block per parent and hide the others.

- **6.20 to 6.29 (Nov 13, released as 6.29): catch-up path order and the Path tab.**
  - **Finished quests travel in the order they were done.** `S.CompletedRank()` reads Questie's journey (`Questie.db.char.journey`, entries `{ Event = "Quest", SubType = "Complete", Quest = id, Timestamp }`, oldest first) into qid -> position; `orderDone()` sorts the done list that way in `MakeSnapshot` and in deltas (anything Questie never saw goes first, by id). A full copy ends with an extra field `^o` (field 11) meaning "this list is in order"; older copies ignore it. `ParseSnapshot` keeps `snap.rank` / `snap.rankMax` / `snap.ordered`, deltas append to `rank`, `SnapshotToString` writes them back in order. The step shows the objective text. Riverglades and other Forever zones often have no objective data in Questie, so a quest turned in to the same NPC that gave it gets a DO step anyway (no location).
